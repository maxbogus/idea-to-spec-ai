# Система правил (для всех ролей)

## Базовые правила

1. **Факт без источника — не факт.** Помечай «допущение».
2. **Пробел — результат.** Пиши «чего не знаем», а не выдумывай.
3. **Три состояния:** факт / гипотеза (в т.ч. допущение) / прогноз.
4. **Вопросы по режиму:** `auto` — 0; `chat` — не больше 3 за гейт;
   `hybrid` — только на критичных развилках (контур, пользователи,
   платежи, интеграции). Спрашивай только то, что меняет следующий шаг.
5. **Проверяй контур:** B2C / B2B / B2G, Россия / трансгранично, локализация.
6. **Проверяй интеграции:** платёжные, государственные, внешние API.
7. **Проверяй данные:** персональные, минимизация, срок хранения (GDPR by design).
8. **Каждый этап заканчивается чеклистом полноты.**
9. **Перед Spec-gate — fact-check** (`subagents/fact-check.md`): факт без
   источника понижается до гипотезы/допущения.
10. **Скилы и методы применяются по `handout-index.md`**, а не «по вкусу».
11. **Каждый вопрос — с объяснением.** В `chat`/`hybrid` вопрос без
    «зачем спрашиваю» и без расшифровки терминов не задаётся (см.
    «Формат вопроса» ниже).

## Формат вопроса (chat / hybrid)

Каждый вопрос задаётся тремя блоками:

1. **Вопрос** — конкретный, меняющий следующий шаг.
2. **Зачем я это спрашиваю** — 2–4 предложения: что этим закрываем,
   какой риск снижаем, что появится на выходе.
3. **Термины** — расшифровка терминов из вопроса (формулировки — из
   «Глоссария терминов» ниже).

Правило действует для любого вопроса, включая стартовый (выбор режима).

## Скилы и методы

- Методы (навыки) — `methods/`: факт/гипотеза/прогноз, содержательно разные
  варианты, стратегия и план проверки, decision-keeper.
- Скилы — `skills/`: сбор источников, модельные персоны, поиск противоречий,
  воспроизводимые расчёты.
- Какая роль что применяет — `handout-index.md`.

## Требования к окружению

Диаграммы рендерятся Mermaid. Нативные use case-диаграммы
(`usecase-beta`, актор = человечек) появились в Mermaid 12.0.0.

- `node` — Node.js 18+;
- `mmdc` — `@mermaid-js/mermaid-cli` **>= 12.0.0**
  (`npm i -g @mermaid-js/mermaid-cli@^12`);
- `make` — GNU make.

Проверка: `make setup` (скрипт `scripts/check-prereqs.sh`). Если версия
ниже — рендер use case-диаграмм упадёт.

## Глоссарий терминов

Короткие расшифровки «человеческим языком» для блока «Термины».

- **JTBD (Jobs To Be Done)** — работа, которую пользователь «нанимает»
  продукт выполнить. Отвечает на «зачем», а не «что».
- **CJM (Customer Journey Map)** — карта пути: этапы → touchpoint →
  действие → эмоция → боль → возможность.
- **Use case** — сценарий взаимодействия актора с системой для
  достижения цели.
- **Персона** — обобщённый портрет пользователя с задачей, контекстом и
  барьерами.
- **Контур** — границы продукта: B2C / B2B / B2G, география,
  локализация, платежи.
- **Success metric** — измеримый показатель успеха с базой и целью (не
  «стало лучше», а «+X к базе»).
- **AS-IS / TO-BE** — как устроено сейчас / как должно быть.
- **Допущение (assumption)** — утверждение без источника; частный случай
  гипотезы, помечается явно.
- **Факт / гипотеза / прогноз** — три состояния утверждения
  (`methods/fact-hypothesis-forecast.md`).
- **Функциональные требования** — что система должна делать (FR).
- **Нефункциональные требования** — как: производительность,
  безопасность, доступность (NFR).
- **Traceability matrix** — таблица связей: BR → FR → UC → тест/гейт.
- **BA-gate / SA-gate / Spec-gate** — контрольные точки готовности
  бизнес-анализа / системного анализа / спецификации.
- **Human-in-the-loop (HITL)** — человек валидирует промежуточный
  результат, а не только финал.

## Антипаттерны

- «Сделать красиво» без критериев.
- Смешивать бизнес- и системный анализ.
- Выдавать гипотезу о решении за потребность.
- Оставлять критерий приёмки неозвученным.
