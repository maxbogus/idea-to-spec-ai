# Воркшоп «От идеи до спецификации с ИИ»

> 2-часовой практический воркшоп: как пройти путь от сырого бизнес-запроса
> до проверяемой спецификации с помощью мультиагентной ИИ-системы — и где
> человек обязан вмешаться.

## Параметры

| Параметр | Значение |
|---|---|
| Длительность | 120 минут |
| Формат | 2 части: спикер 1 — «до спецификации», спикер 2 — архитектура / реализация / пост-релиз |
| Аудитория | продуктовые менеджеры, бизнес/системные аналитики, архитекторы, тимлиды |
| Артефакт участника | черновик требований + спецификации + validation report |
| Упражнения | 45 минут (3 упражнения) |
| Факапы | 10 минут + встроенный fallback |
| Буфер | 10 минут (доп. упражнение, если всё гладко) |

## Сквозной тезис

> ИИ не «угадывает» требования — он интерполирует по тому, что вы дали.
> Чем дальше от данных, тем больше экстраполяции и галлюцинаций. Задача
> воркшопа — дать машине машиночитаемый вход и оставить человеку
> валидацию допущений.

## Источники

- транскрипт подготовки (ASR, восстановлен по смыслу);
- `product_factory` — референс мультиагентной архитектуры (роли, промпты, методы, скилы, fact-check);
- `books/common/knowledge/sdlc/` — каноны ролей, гейтов, жизненных циклов, глоссарий;
- `books/common/templates/` — шаблоны `pdlc_gate_review`, `llm_eval_plan`, `adversarial_validation_checklist`;
- `books/sdlc-book/talks/moscowai-shkola21-2026/` — структура talk-kit.

## Как пользоваться

1. Прочитать `workshop-plan.md` и `transcript-breakdown.md`.
2. Стартовать пробный прогон: вставить сырую идею в `prompts/start.md` — он
   либо развернёт каркас в `output/<run-id>/`, либо пойдёт в диалоге.
3. Прогнать демо по `agenda/part1-before-spec.md` с промптами из `prompts/`.
4. Сверить роль → метод → скил → артефакт → гейт по `handout-index.md`.
5. Раздать участникам `exercises/`, `templates/`, `methods/`, `skills/`.
6. Держать под рукой `faq-fuckups.md` на случай сбоя демо.
7. Передать `agenda/part2-handoff.md` второму спикеру.

## Команды (Makefile)

| Команда | Что делает |
|---|---|
| `make help` | список целей |
| `make scaffold RUN=auto-002` | развернуть каркас прогона из `templates/` в `output/auto-002/` |
| `make render RUN=auto-002` | отрендерить `output/auto-002/diagrams/*.mmd` → PNG |
| `make render-all` | отрендерить диаграммы всех прогонов |
| `make check` | полная проверка: ссылки + code-fences + рендер всех `.mmd` |
| `make check-refs` | проверить, что все ссылки на md/mmd резолвятся |
| `make check-fences` | проверить парность code-fences во всех `.md` |
| `make check-diagrams` | проверить синтаксис всех `.mmd` рендером в temp |
| `make check-bpmn` | проверить, что `.bpmn` — well-formed XML |
| `make check-sync` | проверить, что скилы/шаблоны/скрипты используются и режимы описаны |
| `make list-runs` | список прогонов в `output/` |
| `make start` | показать стартовый промпт `prompts/start.md` |
| `make clean-png` | удалить отрендеренные PNG (source остаются) |
| `make clean-run RUN=auto-002 CONFIRM=yes` | удалить прогон (защищено от случайного запуска) |

Рендер требует `mmdc` (`npm i -g @mermaid-js/mermaid-cli`).
