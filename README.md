# Воркшоп «От идеи до спецификации с ИИ»

> 2-часовой практический воркшоп: как пройти путь от сырого бизнес-запроса
> до проверяемой спецификации с помощью мультиагентной ИИ-системы — и где
> человек обязан вмешаться.

## Параметры

| Параметр | Значение |
|---|---|
| Длительность | 120 минут |
| Формат | 2 части: спикер 1 — «до спецификации», спикер 2 — архитектура / реализация / пост-релиз |
| Аудитория | продуктовые менеджеры, бизнес/системные аналитики, архитекторы, тимлиды |
| Артефакт участника | черновик требований + спецификации + validation report |
| Упражнения | 45 минут (3 упражнения) |
| Факапы | 10 минут + встроенный fallback |
| Буфер | 10 минут (доп. упражнение, если всё гладко) |

## Сквозной тезис

> ИИ не «угадывает» требования — он интерполирует по тому, что вы дали.
> Чем дальше от данных, тем больше экстраполяции и галлюцинаций. Задача
> воркшопа — дать машине машиночитаемый вход и оставить человеку
> валидацию допущений.

## Источники

- транскрипт подготовки (ASR, восстановлен по смыслу);
- `product_factory` — референс мультиагентной архитектуры (роли, промпты, методы, скилы, fact-check);
- `books/common/knowledge/sdlc/` — каноны ролей, гейтов, жизненных циклов, глоссарий;
- `books/common/templates/` — шаблоны `pdlc_gate_review`, `llm_eval_plan`, `adversarial_validation_checklist`;
- `books/sdlc-book/talks/moscowai-shkola21-2026/` — структура talk-kit.

## Как пользоваться

1. Прочитать `workshop-plan.md` и `transcript-breakdown.md`.
2. Прогнать демо по `agenda/part1-before-spec.md` с промптами из `prompts/`.
3. Раздать участникам `exercises/` и `templates/`.
4. Держать под рукой `faq-fuckups.md` на случай сбоя демо.
5. Передать `agenda/part2-handoff.md` второму спикеру.
